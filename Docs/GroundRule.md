## 2. 회의 진행
매일 1회 회의하여 진행 상황을 점검합니다.
| 요일 | 시간 |
|------|-----|
| 주중(학원 O) | 정규 수업시간 내 |
| 주말 및 공휴일(학원 X) | 저녁 11시 |

### 회의 방식
- 주중(학원 O): 오프라인 대면, 회의록에 바로 반영

- 주말 및 공휴일(학원 X): `Slack`을 통해 음성 회의 진행, `Excalidraw Whiteboard`로 회의 내용 기재 후 회의록 반영

## 3. 프로젝트 일정

| 날짜 | 내용 |
|---|---|
| 시작일 ~ 2026-10-09 (D-3) | 팀원별 캘린더에 따라 개발 진행 |
| 2026-10-10 (D-2) | 진행중인 업무 마무리 및 디버깅 |
| 2026-10-11 (D-1) | 발표 준비 |
| 2026-10-12 (D day) | 발표 당일 |

## 3. 매일 해야할 기록들

1. 회의록: 작업 진행도를 점검하고, 회의 안건 및 결정사항은 반드시 기록
2. 업무 일지: 정해진 양식에 맞춰 매일 작성, 개발 및 구현된 부분이 없더라도 꼭 작성

## 4. 작업 방식
1. 구현할 기능에 맞춰 **branch 생성**
2. 다른 팀원의 `씬`과 `프리팹`은 열람만 가능 (접근이 필요하다면 개발 컨벤션 참조) 
3. 업무 진행 중 막힌다면 `4.문제가 발생했을 때`를 참고
4. 구현이 완료된 경우 **PR** 작성
5. PR Merge 이후 **기술 문서** 작성


## 5. 문제가 발생했을 때
### 1. Github의 Issues에 작성
- 구현하려 했던 기능과 해당 기능의 기대 동작
- 구현한 방식 
- 실제 동작하는 결과 (에러 메시지 포함)  
- 해당 문제를 재현할 수 있는 방법

### 2. 문제 해결
문제가 해결되었다면 아래 내용으로 comment를 남기며 Issue를 close합니다.
- 발생한 문제
- 수정한 방식

## 6. 문서화
- 구체적인 작성 방법은 개발 컨벤션 참조
