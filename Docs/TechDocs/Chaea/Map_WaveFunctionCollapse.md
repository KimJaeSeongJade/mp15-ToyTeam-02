# 맵의 절차적 생성

## 📝 1. 기능 개요

### 1.1. 기능 정의

- 파동 함수 붕괴 알고리즘을 사용하여 절차적 맵 생성

### 1.2. 구현 목표

- 샘플 맵을 입력했을 때, 규칙을 세워 맵 생성

- 샘플 맵에서 나타나는 블록의 빈도, 셀 주변의 이웃을 고려하여 가중치를 고려하여 생성

---

## 🛠️ 2. 작성 클래스 설계 및 구조 

### 🔗 2.1. 클래스 간 관계도

## 핵심 클래스 세부 역할

 ### `WaveFunction.cs`

  - **샘플 맵으로 규칙 생성 (`LoadMapData()`)**: 샘플 맵을 입력했을 때, `Tile`을 만들어서 BlockType마다 이웃에 어떤 `Tile`이 들어갈 수 있는지에 대한 규칙 생성 및 빈도를 가중치로 추가

  - **그리드 초기화 (`InitializeGrid()`)**: 무한/빠른 모드의 첫번째 청크는 역과 도구가 배치되어야 하기 때문에 추가로 초기 맵을 입력받고, 빠른 모드의 마지막 청크는 역과 레일이 배치되어야 하기 때문에 마지막 맵을 입력받아 그리드 초기화

  - **셀 후보 제거(`UpdateGeneration()`)**: 청크의 경계면에서도 규칙을 지키기 위해, 청크 가장자리의 정보를 입력하여, 해당 이웃을 고려하여 셀 후보 제거


### `Cell.cs`

  - **붕괴될 셀**: 붕괴 여부 저장 및 자신의 셀에 들어갈 수 있는 `Tile` 후보군을 TileOptions 배열로 저장

### `Tile.cs`

  - **규칙**: 이웃으로 어떤 BlockType이 들어가야 하는지 저장

  - **가중치**: 샘플 맵에서 BlockType이 나타난 빈도를 가중치로 설정

### 🔄 2.2. 파동 붕괴 함수 알고리즘

## 단계별 세부 설명

### 1. 맵 정보 불러오기 (`LoadMapData()`)

- 초기 로딩이면 샘플 맵을 불러와 가중치, 규칙 설정


### 2. 그리드 초기화 (`InitializeGrid()`)

- 초기 로딩이며 게임 모드가 무한/빠른 모드인 경우 초기 맵을 받아 해당 좌표의 셀들은 붕괴시킨 상태에서 값을 저장하고(도구, 역처럼 규칙에 추가하지 않을 블록 타입은 초원으로 대체), 나머지는 그리드를 초기화시켜 새 셀 저장

- 마지막 로딩이며 게임 모드가 빠른 모두인 경우, 마지막 맵을 받아 해당 좌표의 셀들은 붕괴시킨 상태에서 값을 저장하고(도구, 역처럼 규칙에 추가하지 않을 블록 타입은 초원으로 대체), 나머지는 그리드를 초기화시켜 새 셀 저장

- 그 외 상황에서는 모든 좌표에서 새 셀 저장
 <br>

### 3. 셀 후보가 적은 순으로 정렬 (`CheckEntropy()`)

- 후보가 적은 셀부터 붕괴시키기 위해 `TileOption`이 적은 셀이 앞으로 오도록 정렬

### 4. 가중치를 고려하여 셀 붕괴 (`CollapseCell()`, `SelectTile()`)

- 붕괴할 셀을 선택하고 해당 셀을 붕괴

- 4방향 이웃의 블록 타입을 확인하여 더 높은 가중치를 주어 동일한 블록 타입이 뭉쳐서 생성되도록 유도

- 완전 무작위가 아닌, 가중치를 고려하여 확률대로 셀을 붕괴

### 5. 셀 후보 제거 (`UpdateGeneration()`)

- 셀을 붕괴시켰으므로, 모든 셀을 순회하며 후보를 갱신

- 이웃 방향을 확인하며 후보군을 제거

- 청크의 경계면인 경우, 이전 청크 가장자리의 셀을 보며 후보군 갱신

### 6. 맵 데이터 저장 (`GetGeneratedMapData()`)

- 붕괴가 완료되면, 모든 셀을 모아 청크 맵 배열로 생성

- 무한/빠른 모드의 첫번째 청크나 빠른 모드의 마지막 청크면 결과 맵 배열을 기존 블록 타입으로 교체
